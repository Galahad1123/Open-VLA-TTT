# V100 training implementation plan

> **For agentic workers:** Use superpowers:executing-plans. Continue inline under the user's implementation authorization.

**Goal:** Run current master architectures on single-server V100 32GB GPUs without changing master or the shared environment.

**Architecture:** Explicit fp32/bf16/fp16 policy autocast; FP32 model, inner TTT, optimizer and reduction. One dynamic outer loss scale shared by ranks, with bounded deterministic retries at the same successful-update boundary. Persist scale in optimizer control state; reject precision-changing exact resume.

**Tech Stack:** PyTorch 2.11 cu126, Accelerate explicit SUM, Python 3.12, uv isolated project.

**Spec:** User-approved design in this conversation: preserve episode-local fast weights and existing BF16 behavior, no GPU use on development host.

## Global constraints
- Only edit this worktree; no merge, shared environment changes, or GPU jobs.
- Default BF16 unchanged. VLM weights and fast weights FP32. No FSDP or architecture changes.
- Loss scale stays constant across TBPTT/episodes per update; unscale before reduction/clipping.
- Overflow retries do not advance optimizer counters, schedules, sampling, or metrics totals.
- Old non-FP16 checkpoints remain readable; FP16 checkpoints require scaler state.

## Review focus
- Overflow on only one rank, and overflow introduced by SUM.
- Retry chunk sampler without advancing cursor; replay same randomness.
- Resume precision mismatch and missing/corrupt scaler state.
- Forward nonfinite loss must fail clearly instead of endlessly retrying.
- V100 environment must select cu126 for torch AND torchvision, independent of root lock.
