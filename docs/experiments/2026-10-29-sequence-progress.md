# 序列训练进度显示

`train_episode_parallel` 支持 `--progress auto|bar|plain|off`，默认 `auto`。

- `auto`：交互终端显示单行进度；重定向、nohup 环境输出简洁摘要。
- `bar`：强制单行刷新；需要时可配合 `ssh -t` 使用。
- `plain`：最多每60秒输出一次摘要，第一步、阶段切换、保存和结束另行输出。
- `off`：关闭进度摘要，不关闭警告、异常或每步 `metrics.jsonl`。

显示包含 step/本次目标、recipe 总步数、阶段、loss、秒/步、已用时间、ETA、
本机时区的预计完成时刻。`--stop-after` 的目标是本次停止点；恢复训练显示已完成步数，
耗时重新估计。前3步内显示 estimating；交替训练尚未测到的阶段使用已有平均耗时，
并标记 provisional。每阶段保留最近50步耗时，已测保存开销用于估计后续保存时间。
ETA 会随序列长度、硬件负载和保存速度变化，不包括尚未发生且无法测量的开销。

只有全局 rank 0 输出训练进度。完整指标仍每步写入 `metrics.jsonl`，
`logs/rank-N.log` 保留原始输出、异常及进度摘要，不保存动态刷新字符。
窄终端自动使用紧凑格式，完整时区与字段保留在摘要日志中。
模型加载等第三方输出沿用原行为，不统一屏蔽。最后一次检查点保存成功后才显示 complete。

此选项只控制显示，不进入 recipe 或检查点恢复身份。修改不涉及模型、采样或优化器。

验证包括模拟时钟的阶段 ETA、恢复起点/短测目标、TTY 日志分流、失败状态、
主进程限制，以及 off/plain/bar 三种模式的 CPU 训练权重与 loss 逐位一致性。

同步策略：以 master 为基础制作独立提交，向 RoboMME、RMBench、V100 维护分支
cherry-pick；如 runner 上有分支专属逻辑，保留其逻辑，只适配显示调用。
旧实验分支不修改。无需更改现有训练 recipe。
