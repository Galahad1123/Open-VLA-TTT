# LIBERO：每任务 20 次 server-client 评测

本轮固定已训练的本地 Evo-1 Stage 2 80k checkpoint，重新执行四个 suite 的 40 个任务，每任务 20 个初态，共 800 episodes。**全部完成，成功 520 次，整体成功率 65.0%；无基础设施错误，280 次未成功均为达到任务步数上限。**

## 协议与完整性

- Checkpoint：`outputs/libero-local-scratch-seed1000-stage2/checkpoints/080000/pretrained_model`。
- 模型文件 SHA256：`94040fb0dd2c7974619839b86b4acb88df1f8a27280cc0b07ab4861cc1c6891e`，与上次初评相同。
- policy 在主项目 Python 3.12 环境，LIBERO 在独立 Python 3.11 环境；仅通过 localhost:8780 连接。
- 四个 suite：`libero_spatial`、`libero_object`、`libero_goal`、`libero_10`，各 task ID 0–9。
- 每任务使用官方打包初态索引 0–19，seed=1000+episode，即 1000–1019；不是对同一个初态重复 20 次。
- 每任务启动独立环境进程，同一任务内逐 episode reset 环境及 policy/action queue。
- chunk_size=50，n_action_steps=10，32 个 flow 推理步；沿用原 checkpoint 的连续 gripper，不新增二值化。
- 相机采集 256×256，模型输入处理到 448×448；horizons 分别为 280/280/300/520，沿用原有 10 步 reset 稳定动作。
- 全程离线，没有修改模型、processor、训练数据或已有评测结果，没有依测试结果更换 checkpoint。
- 汇总检查了全部 40 个任务文件、各任务恰好 20 个不同 episode ID、每行 seed、模型及 processor 文件身份一致性和错误记录；`complete=true, total_episodes=800, errors=0`。

## 与上次初评的关系与复现性限制

上次每任务 1 次的总体结果为 27/40（67.5%）；本轮 65.0% 使用更多初态，不能将两者之差解释为模型退化，因为模型没有变化。上次结果没有并入本轮分母，初态 0 已重新运行。

额外核对了两轮初态 0：39/40 个任务的成功标志及步数一致；`libero_goal/task3` 上次 300 步超时，本轮 250 步成功。两条记录的 policy metadata 完全一致，config 仅 `episodes` 和输出路径不同。尚未定位变化来源，不能将其归因于某个具体后端或随机源，也不能承诺相同 seed 下逐步确定性。本轮保留原始结果，没有反复重跑择优或替换数据。

Goal task 0/5 等任务表现偏弱，后续可优先通过失败录像和动作轨迹检查原因；仅凭本轮成功率不能确定是训练量、控制误差、状态覆盖或其他因素，更不能直接认定为记忆机制缺失。
